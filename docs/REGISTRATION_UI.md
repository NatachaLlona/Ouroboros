This is the current phase-one registration contract. It supersedes the earlier dated autocomplete/boolean/price examples in ANGULAR.md and FRONTEND.md; their earlier test evidence remains historical. The Angular 22 UI uses the existing API without schema, endpoint, enum or migration changes. Normal data, credentials, permissions and session policy remain untouched.

Only **Voltar ao início** has the enlarged `.home-return` style. Other navigation/action sizes retain their existing rules. ## Platform values and payloads

| Control | Initial state | API behavior |
| --- | --- | --- |
| platform_is_paid, platform_is_episodes, platform_is_duration_time | Unanswered, native checkbox indeterminate | All three are required nonnullable booleans. First activation selects true; another selects false. **Limpar resposta** returns to unanswered. Only explicit true/false passes submission. Persisted values load in edit mode. |
| Price | Empty; placeholder **00,00** | Blank price_amount is omitted from POST, never replaced by null/zero/placeholder text. On PUT, omission preserves a saved price and deliberate clearing sends null; explicit zero stays zero. UI accepts nonnegative integers/comma decimals without grouping or symbols; ambiguous dot/grouped input is rejected with guidance. Exact canonical decimal strings go to the API with a point and no formatting. |
| Currency | No selection | Frontend configuration offers only EUR — Euro, USD — Dólar americano and BRL — Real brasileiro. Code is prominent, name below; only the code is submitted. No locale inference, rates or balances. Blank is null. Unknown historical codes are disclosed and preserved until explicitly replaced. |
| Onde acessar | Empty | Only Aplicativo → application and Site → website are new choices. The API still accepts its existing array enum, including link/multiple members. UI sends [] or singleton arrays. Legacy arrays remain unchanged on unrelated edits; an explicit new selection replaces the full array. |
| URL | Hidden until Site is selected | Switching to Aplicativo hides the input but retains its non-secret URL draft. Returning to Site restores it. Non-Site POST omits the hidden URL. Changing a persisted Site/legacy record to Aplicativo explicitly sends platform_url=null on PUT. Loading/saving unrelated fields never silently clears legacy URLs/types. Success/reset clears the retained draft. |

The API price is an unconstrained nonnegative finite PostgreSQL NUMERIC, and currency is optional independent text. No new price/currency pairing or two-decimal storage constraint is invented. Input parsing is a small shared explicit implementation; Angular does not provide a native decimal-comma input mask or tri-state business checkbox policy. Existing Signal Forms provide normal required/max-length field facilities; the registration boundary validates all required boolean answers before generating a payload.

Monetary **presentation** uses installed Angular [formatCurrency](https://angular.dev/api/common/formatCurrency) with **pt-PT** locale and **1.2-2** digits. Formatting happens on blur, never on each keystroke; focus restores the exact editable value. For example 23 → 23,00; 23,5 → 23,50. The exact API decimal is separate: extra precision is preserved and explicitly shown when the two-place presentation rounds it. Decimal-string/BigInt arithmetic and an exact-text fallback prevent floating-point display loss for large values; no API amount is rounded through JavaScript Number. Scientific notation from existing server Decimal responses is expanded exactly for editing. No new input fields or dependencies are added.

## Name suggestions

The dropdown is anchored directly below the input inside its positioned wrapper, outside normal layout flow. Existing escaped case-insensitive substring predicates and deterministic display-name/ID ordering remain. Requests debounce 250 ms and use page=1/page_size=20; at most twenty records are displayed. There are no previous/next/load-more controls in this autocomplete. A twenty-result response shows **Continue digitando para refinar a busca** in muted text.

Mouse/touchpad/touch scroll, native scrollbar, arrows, Enter and Escape work with the existing combobox semantics. No matches produce no dropdown or permanent empty-results block. Lookup failure has discreet separate feedback and retry. Stale responses are disregarded on typing, resource changes and destruction. Selection opens the existing edit confirmation; Enter accepts a highlighted/unique-prefix suggestion or completes the name field, never creates a record. Technical names are not shown in results. Consultation pagination is unchanged.

## Classification position

**Classificação da Obra** loads current classifications ordered by actual numeric tier, in bounded pages of up to 50. All pages must succeed before the order is presented as complete. Count drift, duplicated/missing positions or failures block submission and offer **Atualizar ordem**; separate page requests are not a frozen snapshot. The server still validates and reorders atomically in the mutation transaction.

The current order and selector show actual `tier. display_name_work_classifications`, never the technical name. Creation defaults to **Adicionar ao final (N+1)** and omits tier. Choosing an occupied position submits only that tier; the backend shifts later positions. Edit preselects the persisted tier and offers 1..N move positions without an invalid N+1 append. Angular never updates the other classifications itself.


## Current phase-one forms, cancellation and consultation

The same resource-specific field definitions, validation, formatting and templates serve creation and editing. Primary actions are exactly **Cadastrar** and **Salvar edição**. **Cancelar** is available in both modes. The shared registration controls still preserve initial unanswered platform checkboxes, explicit false, optional exact prices, frontend currency configuration, legacy access members and conditional URL drafts. Brazilian Portuguese labels are **Onde acessar**, **Aplicativo**, **Site** and **URL**. Autocomplete now shows up to **20** first-page matches; this limit never changes consultation's **10-item** pages.

### Unsaved changes and confirmation hierarchy

The Angular [CanDeactivateFn](https://angular.dev/api/router/CanDeactivateFn) guard and the shared UnsavedChanges service ask before abandoning dirty forms through route navigation, Cancelar, resource switching or logout. Choosing **Cancelar e continuar editando** preserves the draft and session. Confirming discard resets the unsaved values and permits the requested action. Restoring original values makes the form clean; validation messages alone do not make it dirty. Confirmed save success never causes another discard prompt. Ordinary saves have no redundant edit confirmation. An in-flight mutation blocks app navigation/logout rather than risking an automatic replay.

Browser close/reload uses the browser-owned beforeunload confirmation while dirty. Browsers control that native prompt's wording/appearance and may require prior user interaction; this cannot be replaced with an asynchronous custom modal at unload. The custom router/dialog behavior and native browser behavior need distinct verification.

All shared modification dialogs emphasize **Cancelar** with the filled primary treatment. Affirmative buttons are secondary, readable, type=button, and never receive initial focus. Default focus goes to cancellation; pressing Enter without deliberately focusing an affirmative control cannot implicitly submit a destructive form. An explicitly focused affirmative button retains standard keyboard activation. Escape cancels except while a confirmed operation is already in flight. Direct editing from consultation stays direct; existing-suggestion edit confirmation is retained.

### Compact selected-field filters and return from editing

Consultation opens its list directly at page 1/page_size 10 unless restoring an edit-return context. It uses server count/page/page_size/items and existing previous/next controls. **No Cadastrar button appears in consultation.** Deletion refreshes list/count and recovers to the last existing page when necessary.

The shared CatalogueFilters component keeps **Pesquisar** below its **Filtros avançados** trigger in a fixed primary column, alongside always-visible **Limpar filtros**. The checkbox picker is an absolute overlay rather than an in-flow expansion, opening beside the primary controls on desktop and above the trigger on small screens so it does not cover Search/Clear. Additional selected value controls use adjacent desktop space and stack after the primary controls on mobile. Only checked public filter fields render value controls. Removing one removes its value and refreshes the query without that predicate. Search closes the picker; Escape restores trigger focus and outside clicks close it. Public filter types, literal substring matching, exact-day/range/timezone validation and deterministic scalar ordering remain the existing API contracts. No Works or complex tag filters are introduced.

**Pesquisas recentes** keeps at most five successful user-applied criteria sets per resource, with value copies rather than results. Initial automatic loads, pagination, deletion refresh and failed requests are not added as searches. Reapplying restores criteria/selected fields/order and starts at page 1; **Limpar histórico** clears that resource's history. Storage is bounded service memory only, never web storage, URLs or a backend preference. Logout, expiry and a new signed-in session clear all contexts/history. A UI-only session generation counter separates successive sign-ins; it does not alter bearer/credential-version validation or the browser lifetime policy.

Before opening a row for editing, consultation records its resource, successful applied filters/order, page and scroll. Returning after save/cancel/back recreates the list with those criteria, refreshes that page and restores scroll after rows render. Only non-secret criteria and navigation numbers are retained, not response rows or authentication material. A full page reload creates a new in-memory frontend state; persistence across reloads is not introduced.

Its nominal CSS contrast is **1.731:1 on paper #FFFCF6** and **1.602:1 on cream #F7F3EB**, so it is decorative rather than the sole readable indication of required status. Existing label text #424A40 measures **8.974:1** on paper and **8.303:1** on cream; the legend's existing muted #655D56 measures **6.303:1** and **5.832:1** respectively. Required semantics remain present, and decorative stars are aria-hidden with a dark outline. These calculations use the declared CSS surfaces/text colors, not a browser screenshot measurement. Legend placement, remaining palette, circular logo, Ouroboros wordmark and unrelated control sizes are preserved.
